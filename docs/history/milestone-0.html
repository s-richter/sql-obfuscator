The design we agreed on

A script passes through four states on your machine. Only the obfuscated one may be shown to an LLM. The mapping records every replacement and is what turns a response back into real names.

  • Names become an adjective and an animal, such as frozen_lion. Qualified names are replaced part by part, and the fake name follows the casing of the original.
  • Strings become numbered placeholders such as 'text_017'. Numbers are kept unless you switch number obfuscation on.
  • Comments become markers such as /* c12 */ and are put back afterwards.
  • Four checks run on every obfuscation: round-trip, leak, structure and ban-list. If one fails, nothing is written, and there is no override.

The decision everything else rests on

docs/adr/0001-token-first-engine.md

You asked for sqlglot for robustness. For plain queries its parser is robust. For stored procedures, which are 20 to 30 percent of your scripts, it fails in three different ways, and two of them are silent.

What the parser doesExamplesConsequence for obfuscation
Refuses the scriptGO, THROW, IF … ELSE around UPDATELoud and safe, but most procedures would be rejected.
Treats a block as opaque textTRY/CATCH, cursors, triggersNames inside are invisible to the syntax tree and would pass through unobfuscated.
Rewrites into invalid SQL without an errorIF @x IS NULL SET @x = 1 becomes IF @x IS NULL AS SET BEGIN @x = 1Corrupted output that no idempotence check or name comparison detects.

So the engine renames on the token stream. Every name that is not on the keep-list is replaced, which means a mistake produces too much obfuscation and never a leak. The parser is used only for pretty-printing statements it handles safely.

How we got here

The design was settled in four rounds of questions, 33 in all, each with a recommendation. Building started only after you confirmed a shared understanding.

  1. Before round 1
    Read your requirements and probed sqlglot on representative T-SQL and Hive.
    Finding: the parser cannot carry stored procedures.
  2. Round 1 · Q1–10
    Threat model, token-first engine, per-part mapping in one namespace, strings replaced and numbers kept, comment markers, the bundle, one workspace model, terminology.
    Your input: 20 to 30 percent procedures with GO; multi-user and auto-update are commitments, not options.
  3. Round 2 · Q11–20
    Best-effort formatting, a stored mapping that only grows, numbered placeholders, keep-list, workspace layout, commands and flags, checks that cannot be overridden, ban-list matching, stack.
    Finding: comparing names before and after formatting does not catch the silent rewrites.
  4. Round 3 · Q21–29

    Your input: the earlier tool failed because its command line and handling grew too complicated.

    Correction: I had said the tokenizer handles everything. It does only with command mode off.
  6. Round 4 · Q30–33

    Your input: the number rule has to be documented clearly.

Decisions on record

No.DecisionMain reason
0001The engine renames on the token stream, not the syntax tree.The parser leaks or corrupts procedural T-SQL.
0002We protect names and values, not structure. Four checks, no override.The LLM needs the structure to be useful.
0003Names map per part, in one case-insensitive namespace.The engine never has to know what kind of thing a name is.
0004The stored mapping is the source of truth and only grows.Names stay stable when originals change, which auto-update needs.
0005Formatting is best-effort and limited to safe statement types.An allow-list is the only gate that stops silent rewrites.
0006Five commands, independent flags, no safety switches.The earlier tool became too complicated to use.
0007Numbers are replaced by size, not by position. Proposed since 13 October, until milestone 2 has tested it.Tokens cannot tell a threshold from a row limit.

What I would do differently

Six things, in order of how much they cost.

1. Ask about earlier attempts in the first round

Happened
I found sql-obfuscator_deprecated by accident after round 2, while checking GitHub access, and asked about it in round 3.
Cost
I recommended the token-first engine before testing it on 9,689 lines of your own scripts, and I proposed six commands in round 2 before hearing that complexity sank the earlier tool. One command was cut again in round 4.
Instead
First question of round 1: "Has this been tried before, and what do you have from it?"

2. Put a claim in a test before putting it in a decision record

Happened
Two statements in decision record 0001 were wrong as first written. "The tokenizer handled every construct" came from a probe that never put GO, FETCH or PRINT at the start of a statement. "IF … ELSE is rejected" generalised from one example.
Cost
Two corrections to you, and a recommendation that was right for a reason I had not fully checked.
Instead
Write tests/test_sqlglot_assumptions.py first and let a decision record say only what a test shows. That file exists now; it should have existed before round 1 ended.

3. Show you real output before asking you to agree to rules

Happened
Each round had about ten questions and nearly every answer was "agree".
Cost
Unknown, which is the problem. The recommendations may have been right, or the questions may have been too abstract to disagree with. You have not yet seen what Frozen_Lion and 'text_017' look like across a 500-line procedure.
Instead
Obfuscate one of your sample scripts with the throwaway version in round 1 and put the result in front of you. It took minutes to write.

4. Try the number rule before recording it as accepted

Happened
We agreed "four or more digits or a decimal point" in the abstract. Shortly afterwards, writing the literals script showed that $1250.75 does not even arrive as one number.
Cost
None yet. But decision record 0007 and the user-facing page state a rule that has never run against a script.
Instead
Mark 0007 as proposed until milestone 2 has run it against script 37.
Since
Done on 13 October in pull request #3: 0007 is now proposed.

5. Keep each fact in one place

Happened
The list of checks lived in three documents. I added the structure check to one and missed the other two.
Cost
Pull request #1 the next day.
Instead
State the checks once and link to that place. They are still listed in three files today.

6. Check access first, and commit in reviewable pieces

Happened
I learned that I could not create a repo only after you had confirmed everything. Milestone 0 then went to main as one commit of 81 files.
Cost
A detour through GitHub app settings, and decisions, scripts and code that you could not review separately.
Instead
Check repo access during round 1, and open separate pull requests for the documents, the scripts and the code.

What is not verified

  • The new scripts have never run on SQL Server or Hive. I wrote the 21 new scripts to be valid, but they were only tokenized. A syntax error in one would not have been caught.
  • No real script of yours has been through anything. Everything so far ran on invented samples.
  • Formatting is untested on the scripts. The allow-list in decision record 0005 comes from individual probes, not from a run over all 49.
  • The keep-list does not exist. It is the largest piece of milestone 1. Without it, words like OPEN and WHILE get fake names.
  • The round-trip result is from throwaway code. The repo contains nothing that obfuscates.
